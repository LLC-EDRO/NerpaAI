# Кастомные презентации V3

В backend перенесён движок из `nerpa.ai/backend/src/presentations/agents/uploaded-template/engine` и его Python-пакет. Исходный проект не изменяется. Файлы frontend не изменены.

## Что перенесено

- Импорт пользовательского PPTX: объекты, шрифты, оформление, данные диаграмм и таблиц, исходные макеты и HTML-профили.
- Планирование по теме и материалам, выбор макетов и привязка подтверждённых данных.
- Генерация содержания и HTML/CSS слайдов, измерение фактической вёрстки, смысловая и визуальная оценка, ограниченное исправление проблемных слайдов.
- Экспорт PPTX/PDF с сохранением поддерживаемых редактируемых объектов PowerPoint и промежуточных JSON-документов.
- Импорт JSON, JSONL, NDJSON, CSV, TSV, XLSX, XLS, XLSM, ODS, TXT и Markdown из серверного парсера nerpa.ai. Дополнительно реализован XML: повторяющиеся записи с полями или атрибутами. DTD и пользовательские сущности запрещены; XML не исполняется.

Генерируемый HTML — внутренний формат серверного рендера слайдов. Клиентское приложение сюда не переносилось.

## Интеграция с NerpaAIFree

`src/custom-presentations/engine/` содержит перенесённые алгоритмы; `src/custom-presentations/pipeline.ts` подключает их к существующим серверным маршрутам. Новые проекты получают `engineVersion: custom-v3`. Ранее сохранённые проекты без этой отметки продолжают использовать прежний движок.

Запросы к модели направляются в OpenAI-совместимый API `ai-demo.platformpreview.ru` через `/v1/chat/completions`; модель — `qwen38-27b-fp8`. Заголовки: `Authorization: Bearer <API_KEY>`, `Project-ID: <PROJECT_ID>`, `Content-Type: application/json`. Сохраняются отмена задач и локальное JSON-хранение. Старые снимки настроек проектов также используют новое серверное подключение. Веб-поиск и генерация новых картинок остаются отключёнными согласно настройкам открытой версии; загрузка собственных изображений работает через существующий API.

Источник PPTX остаётся неизменным. Выбранные исходные слайды также собираются в отдельный PPTX для существующего маршрута скачивания. Подтверждённые файлы данных и их SHA-256 хранятся в каталоге своего проекта; перед планированием сервер читает собственные квитанции вместо значений, присланных клиентом. Изменение состава файлов сбрасывает план и результат.

## Запуск

Из корня проекта установите зависимости backend и соберите отдельный образ нового обработчика:

```powershell
npm --prefix backend ci
npm --prefix backend run sandbox:custom
npm --prefix backend run dev
```

Docker Desktop должен работать в режиме Linux-контейнеров. Образ V3 содержит Python 3.12, Chromium, LibreOffice и зависимости из `vendor/custom-presentation-agent/requirements.txt`.

Переменная `CUSTOM_PRESENTATION_SANDBOX_IMAGE` задаёт образ V3; значение по умолчанию — `nerpa-free-pptx:3`. Старый `PRESENTATION_SANDBOX_IMAGE` сохранён для ранее созданных проектов. Пересоберите V3-образ после изменения Python-файлов. Текущий `backend/.env` не менялся. Реальный ключ сохранён в игнорируемом Git файле `backend/.env.inference.local`, который автоматически загружает backend. Переменные окружения сервера имеют приоритет. После клонирования задайте `API_KEY`, `PROJECT_ID`, `INFERENCE_BASE_URL` и `INFERENCE_MODEL` в окружении сервера или этом локальном файле. Файлы `.env` и их примеры не публикуются в репозитории. Не требуется дублировать `/v1` или передавать `scope`.

## API файлов данных

Маршруты доступны для локальных проектов:

- `POST /api/projects/:id/data` — multipart-форма с одним полем `file`; ответ `{source, project}`. До 10 МБ на файл, до 6 файлов на проект.
- `GET /api/projects/:id/data` — `{sources: [...]}` с квитанциями разбора.
- `DELETE /api/projects/:id/data/:sourceId` — удаление источника и сброс текущего плана.
- `POST /api/projects/:id/plan` — прежние поля `topic`, `count`, `sourceText` и необязательное `dataSourceIds: string[]`. Если список не передан, используются все загруженные источники; пустой список исключает их из нового плана.

Порядок работы: загрузить PPTX → дождаться импорта → загрузить файлы данных → создать и утвердить план → вызвать прежние `assemble` и `fill`.

Промежуточные документы остаются в `data/projects/<id>/`: `source/`, `data-sources/`, `plan-rN.json`, `template-rN.json`, `filled-rN.json`, `output-rN/`, журналы моделей и исправлений. Через существующий маршрут файлов дополнительно доступны `output/html-scenes.json` и `output/html-generation-report.json`.

`GET /api/health` дополнительно возвращает `customEngine`, `customSandbox` и `dataFormats`. Установленный пакет без собранного Docker-образа не означает готовность экспортёра.

## Происхождение кода

`custom-presentation-upstream.json` перечисляет исходные файлы движка и их SHA-256 на момент переноса. Адаптации относятся к указанному inference API, общему классу серверных ошибок, отмене запросов и сборке выбранного исходного PPTX для существующего API. Платёжная система, авторизация, PostgreSQL и интерфейс nerpa.ai не переносились.

По запросу пользователя дальнейшее тестирование остановлено. Полная генерация и экспорт через V3-контейнер после интеграции не подтверждены.

## Защита локальной конфигурации в Git

Реальные `.env`, их примеры, ключи, сертификаты, локальные данные, сборки, зависимости и рабочие каталоги исключены через `.gitignore`. `backend/.env` и `backend/.env.example` удалены из индекса Git с сохранением локальных файлов.

Хуки `.githooks/pre-commit` и `.githooks/pre-push` запускают `scripts/check-secrets.mjs`: проверяют индекс и публикуемые Git-объекты, не выводя значения секретов. В этом checkout хуки включены. После нового клонирования их можно включить командой `git config --local core.hooksPath .githooks`.
